# Вклад в vishap-generator

Спасибо за интерес к проекту.

## Как сообщить о баге
1. Проверьте, нет ли уже такого Issue.
2. Создайте Issue по шаблону «Bug report».
3. Приложите `spec.yaml` (без секретов), команду, ожидаемое и фактическое поведение. Если есть трасса `.vishap/*.trace.json`, она помогает больше всего.

## Как предложить фичу
1. Issue по шаблону «Feature request».
2. Опишите, какую проблему это решит. Скажите, какой этап затрагивает: Intake, Design, Build, Verify или Deliver.

## Как отправить Pull Request
1. Ветка: `git checkout -b feature/my-feature`.
2. Тесты проходят: `python run_tests.py` (без сети и без модели). Для линтера и версии: `python run_tests.py --lint`.
3. Новое поведение покрыто тестом. Модель в тестах заменяется заглушкой (`tests/test_pipeline.py: Stub`).
4. Отправьте PR по шаблону.

## Правила кода
- Только стандартная библиотека и PyYAML; новая зависимость обсуждается отдельно.
- Промпты лежат файлами в `src/generator/prompts/`, не в Python-коде. Новый промпт добавьте в `pipeline/stages.py`.
- Данные пользователя попадают в модель только через `wrap_data()`.
- Не ослабляйте гейт ради зелёного теста: вердикт «не доказано» не должен превращаться в «прошло».
- Ключи модели не пишутся ни в файлы, ни в логи, ни в тесты.

## Лицензия
Отправляя PR, вы соглашаетесь, что ваш вклад распространяется под AGPL-3.0-or-later.
