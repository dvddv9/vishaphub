- **Explained surprise:** `cmd-popen` / `fix`. The patch is the right fix and its command-injection probe went from reproduced to not reproduced. The status is `FIX_PARTIAL` because the rules also raised a `path-traversal` finding (CWE-22, medium) on `os.popen(...).read()`, which is a misclassification by the rules, and the patch check demands an exploit test for every attack class whose finding disappeared. So a false positive of the rules turned into a missing-test gap. The check did what it is built to do; the cost of the rules' wrong guess is paid in a `PARTIAL` that says exactly what is missing.
- **Limit confirmed:** `cmd-system` / `gut-function` got `FIX_VERIFIED`. KNOWN LIMIT: this case's own test asserts nothing, so a function that does nothing passes it

## What this does not show

- The corpus is small, written by us, and its truth is true by construction. Agreement with it is a check that the tools do what they were built to do, not an accuracy figure on real code.
- Python only. The probes need the caller to name the function to attack.
- No model produced any of these patches. How good model patches are, and how often the checking loop converges, was not measured (that would send code to a provider and needs the go/no-go for external processing first).
- One machine, one run; the times are indicative.
- This document makes no claim that the hub fixes vulnerabilities automatically.
