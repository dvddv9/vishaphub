# Ограничения

Что генератор не делает и где его вердикту нельзя верить вслепую.

- **Нет изоляции Verify.** Код модели исполняется дочерним процессом с правами пользователя (очищенное окружение, таймаут). Враждебный код это не остановит. Нужен Docker или похожая клетка.
- **Только `python/*`.** Цели других языков проверяются только на уровне плана; тесты и атаки Verify работают для Python.
- **Атаки Verify: `http-endpoint`** со входами в `query`, `header`, `path` и `body`. Для `path` в `route` должен быть placeholder (`<имя>`, `<тип:имя>`, `{имя}`), иначе вход пропускается с пояснением; для `body` значение идёт плоским JSON-объектом `{"имя": значение}`, вложенные поля, массивы и другие типы содержимого (формы, файлы) не атакуются. Значение в `path` не бывает «отсутствует» или «пустое»: это другой маршрут.
- **Без базы данных.** Verify идёт без БД: ветки 200 и 404 доказаны тестами модели с подставной базой, на настоящей БД Verify не проверяет.
- **Покрытие строчное**, без веток. Встроенный счётчик (когда нет пакета `coverage`) считает исполняемые строки через `co_lines`.
- **Нет проверки библиотек по документации.** `library_check` только называет библиотеки.
- **Свободный `text`** читает модель; требования создаются только из структурных полей. Факт, сказанный лишь в `text`, считается отсутствующим (сверка `textcheck` может на него указать, но не блокирует).
- **Анализатор** отправляет код своей модели; без его команды проверка `skipped`.
- **Один прогон за раз** на сервере; нет аккаунтов, очереди и квот.
- **Docker-файлы** написаны, но в тестах репозитория не запускались. `pip install -e .` на Windows пользователя не проверялся: запасной путь `$env:PYTHONPATH="src"; python -m generator ...`.
- **Redact ловит типичные формы секретов** (ключи известных провайдеров, приватные ключи, JWT, пароли в URL и `password = ...`), не всё. Секрет в свободном тексте остаётся секретом: не пишите его в spec.
- **Задачи API живут в памяти** сервера час и пропадают с его остановкой; лимит запросов считается по адресу сокета (за прокси лимит общий).
- **Цена в отчёте** есть только если заданы `GENERATOR_PRICE_IN` и `GENERATOR_PRICE_OUT`; токены считаются, только если конечная точка их сообщает.
- **STRIDE читает spec, не код.** `covered` значит «в spec есть требование, которое проверит Verify», не «код безопасен». Правила простые (слова audit, role, rate limit; коды 401/403 и 400/422) и перечислены в `tools/stride.py`.
- **COVE: расхождение — эвристика.** Либо код не делает то, что сказано в spec, либо spec двусмысленна; генератор не решает, что из двух. Проба нужна машиночитаемому правилу входа (`1-64 letters and digits`) и `http-endpoint` на `python/*`. `unclear` не считается расхождением.
- **Кандидаты стоят N сборок** и отличаются только настолько, насколько их различает выборка модели: при температуре 0 это один и тот же ответ (`--repro` с несколькими кандидатами отказывает).
- **Поиск инструкций в spec узкий**: частые формулировки на английском и русском, не все возможные. Это находка, не защита: защита в том, что spec идёт к модели как данные между маркерами.
- **Новые проверки на настоящей модели не гонялись**: только на заглушке.
- **Публичная демо-страница (`render.yaml`) только проверяет спецификацию.** Генерация и запуск кода на публичном адресе не включены намеренно: у сервера нет аккаунтов и квот, а Verify не изолирует код. Лимит запросов на Render общий для всех посетителей (адрес сокета — прокси).
