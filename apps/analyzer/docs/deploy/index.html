Deploying Vishap

Vishap ships as a single container image plus a Compose file. This page covers running it anywhere Docker runs; the VPS-specific checklist (TLS, CI secrets, rollback) lives in deploy/README.md.

Automated deployment is not wired up yet (v6.4). CI only verifies that the image builds (.github/workflows/docker-build.yml, no registry push). Follow the VPS checklist manually until the deploy job is re-enabled.

Quick start (local, Docker)​

git clone https://github.com/dvddv9/vishap.git
cd vishap
cp .env.example .env
# fill in DATABASE_URL, CONVEYOR_API_KEY, STRIPE_SECRET_KEY, CLERK_SECRET_KEY
docker compose up -d postgres redis
alembic upgrade head
docker compose up -d

The API answers on http://localhost:5001/health; interactive docs are at /docs.

Environment variables​

The API validates a subset of the environment at startup and refuses to start if a required value is missing:

VariableRequiredPurpose
DATABASE_URLyesPostgres connection string (postgresql+asyncpg://...)
STRIPE_SECRET_KEYyesCheckout, invoices, price listing
CLERK_SECRET_KEYyesAuthentication
CONVEYOR_API_KEYin productionAPI-key auth; also makes the server bind 0.0.0.0
STRIPE_WEBHOOK_SECRETfor billingVerifies Stripe webhook signatures
STRIPE_PRICE_IDfor checkoutPrice created by python -m src.billing.stripe_setup
CLERK_JWKS_URLfor /analyze/secureToken verification keys
POSTGRES_PASSWORDproduction composePostgres password
FERNET_KEYyes for secretsEncrypts stored integration secrets
OTEL_EXPORTER_OTLP_ENDPOINTnoTrace export; empty disables it

VISHAP_DEV=true downgrades the startup check to a warning, which is how the demo environment runs without Stripe or Clerk keys.

Why CONVEYOR_API_KEY matters in production​

python -m src.main binds 127.0.0.1 when no API key is configured — a deliberate safety default for laptops. In a container that means the port is reachable from inside the container only, so a reverse proxy gets connection refused while the container health check stays green. Set the key.

Migrations​

alembic upgrade head          # apply
alembic downgrade -1          # roll back one revision
alembic current               # what is applied

Revisions 002_add_rls_jobs and 003_force_rls install row-level security on jobs. 003 makes the policy apply to the table owner too, so every code path must bind a tenant (the API does this in its request handlers).

Reverse proxy​

The compose file binds the API to 127.0.0.1:5001. Terminate TLS in front:

api.example.com {
    reverse_proxy 127.0.0.1:5001
}

Forward Host and keep request bodies unmodified — Stripe's signature covers the raw payload.

Health and observability​

EndpointMeaning
GET /healthliveness; used by the container health check
GET /metricsPrometheus exposition
GET /billing/productsactive prices, [] when Stripe is unconfigured

Traces go to Tempo via OTLP (http://tempo:4318 inside the compose network) and are visible in Grafana. Tracing is fail-open: if the collector is down, requests still succeed.

Building the image yourself​

docker build -t vishap-analyzer:local .
docker run --rm -p 5001:5001 --env-file .env vishap-analyzer:local

The Dockerfile is a two-stage build: dependencies are installed in a builder stage (cached as long as requirements.txt is unchanged), the runtime stage carries only the installed packages, curl for the health check, and runs as the non-root vishap user.

Upgrades​

CI builds and pushes :latest and :<git-sha> on every push to main, then deploys over SSH. To roll back, pin the previous SHA:

IMAGE_TAG=<sha> docker compose -f deploy/docker-compose.prod.yml up -d api worker

Troubleshooting​

SymptomLikely cause
Missing env vars: DATABASE_URL... on startvalidate_config() — fill .env or set VISHAP_DEV=true
API healthy in-container, unreachable outsideCONVEYOR_API_KEY unset → bound to loopback
Stripe webhooks return 400STRIPE_WEBHOOK_SECRET missing or body was modified by a proxy
Stripe webhooks return 500STRIPE_WEBHOOK_SECRET not set at all
Jobs stay queuedworker not running, or JOB_STORE differs between api and worker
/analyze/secure returns 401 "Clerk not configured"CLERK_JWKS_URL empty
