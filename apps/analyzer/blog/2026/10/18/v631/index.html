Vishap v6.3.1 — Multi-tenant RLS + Audit Export

October 18, 2026 · 3 min read

v6.3.1 is the release where isolation moved from application code into the database, and where the audit trail became something you can hand to an auditor instead of something you read in a dashboard.

Row-level security​

Jobs are now isolated by a PostgreSQL policy rather than by remembering to add a WHERE tenant_id = ... to every query. Every request binds a tenant, and the policy restricts SELECT, INSERT, UPDATE and DELETE to rows belonging to it. FORCE ROW LEVEL SECURITY extends that to the table owner, so a future migration script cannot quietly bypass it.

The application also sets the tenant on each session through set_config('app.current_tenant', ..., true), which means a query that forgets to filter is still filtered by the database. Two independent layers, one mistake required in each.

This release also fixed a real bug found while building it: the PostgreSQL job store is async, and its coroutines were never awaited. Async update paths returned a pending coroutine and silently did nothing. The store interface is now fully async end to end.

Audit export​

GET /audit/export?format=csv and ?format=json return the caller's job trail with filters for date range, status and limit. The CSV streams row by row; the JSON mirrors the same eight columns. Report bodies are deliberately excluded — an auditor wants to know who did what and when, not the contents of a report.

This is the artifact SOC 2 and ISO 27001 evidence collection actually asks for.

GDPR endpoints​

GET /api/me/data exports every job and history entry for the tenant; DELETE /api/me erases them. Both are scoped by tenant, and both require a Clerk session.

SSO is stubbed, on purpose​

GET /auth/sso/login and POST /auth/sso/callback answer 501 Not Implemented with a clear detail message. SAML requires the Clerk Enterprise tier; returning an explicit 501 is more useful to integrators than a fake redirect, and it documents the plan boundary in code.

Two case studies on curl​

We ran the analyser over lib/cookie.c and lib/http2.c from curl. Nine findings across five CWE classes, including a potential data race and a NUL bypass in cookie validation. None is a proof of concept, and the reports say so. Both are published, along with a draft disclosure note.

Fixed: MDX comments​

The documentation site has been failing to build since the legal pages landed: Docusaurus compiles .md as MDX, and MDX does not accept HTML comments. The mirrors now use the MDX comment syntax. If your own site mixes HTML comments into Markdown, this is the release that would have caught it for us.
