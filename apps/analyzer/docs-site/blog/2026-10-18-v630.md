v6.3.0 replaces the Streamlit prototype with a Next.js dashboard, adds
OpenTelemetry tracing across the whole pipeline, and turns multi-tenant
isolation into something the database enforces rather than something each query
is expected to remember.

{/* truncate */}

## A real UI

The new dashboard is Next.js 16 with Clerk authentication. It does three things
the prototype could not: it shows a list of jobs with live status, it renders
reports as formatted Markdown instead of a text blob, and it keeps a per-browser
job history you can return to.

The analyse form takes a file or pasted material, submits the job, polls it, and
redirects to the report when the pipeline finishes. Nothing else to learn.

## Tracing you can follow

Every analysis produces an OpenTelemetry trace: one span per pipeline stage, one
for the Celery task, exported over OTLP to Tempo and readable in Grafana. When a
job takes 40 seconds instead of 12, you can see which stage spent the time rather
than guessing.

The instrumentation is fail-open. If OpenTelemetry is not installed or
`OTEL_SDK_DISABLED` is set, the application runs exactly as before and the spans
become no-ops. Tracing never becomes a startup dependency.

## Multi-tenant isolation in the database

Jobs are now isolated with PostgreSQL row-level security. Each request binds a
tenant, and a policy restricts `SELECT`, `INSERT`, `UPDATE` and `DELETE` to rows
belonging to that tenant — including the table owner, once
`FORCE ROW LEVEL SECURITY` is enabled. The application also sets the tenant on
every session it opens, so a query that forgets to filter is still filtered.

This matters more than it sounds. Isolation that lives only in application code
is one forgotten `WHERE` away from a cross-tenant leak. Isolation that lives in
a policy is not.

## The basics

- The job store is fully async, which fixed a real bug: the PostgreSQL backend's
  coroutines were never awaited, so async update paths silently did nothing.
- The analysis history is tenant-scoped, including legacy rows with no tenant,
  which belong to `public`.
- Audit-trail export is available as CSV or JSON for compliance collection.

Upgrade notes are in the [documentation](/docs/getting-started).
