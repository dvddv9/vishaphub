# Payment Service — Техническое задание v1.2

## 1. Функциональные требования

1.1. Обработка платежей с latency < 500ms (p95).
1.2. Поддержка карт Visa, Mastercard, МИР.
1.3. Хранение данных карт в соответствии с PCI-DSS.
1.4. Логирование всех транзакций для аудита (включая полный PAN).
1.5. Retry платежей при timeout upstream до 3 раз.
1.6. Идемпотентность: повторный запрос с тем же idempotency-key не создаёт дубль.

## 2. Нефункциональные требования

2.1. Доступность 99.99% (SLA).
2.2. RPO 0, RTO < 5 мин.
2.3. Шифрование at-rest: AES-256.
2.4. Шифрование in-transit: TLS 1.3.

## 3. Противоречия и риски

- Требование 1.3 (PCI-DSS) vs 1.4 (логирование PAN) — **прямое противоречие**. PCI-DSS запрещает хранение PAN в логах.
- Требование 1.5 (retry до 3 раз) vs 1.6 (идемпотентность) — **неполная спецификация**. Не указан алгоритм генерации idempotency-key при retry.
- Требование 2.1 (99.99%) vs 1.5 (retry) — при retry latency растёт, SLA под угрозой. Нет timeout-бюджета.
- Требование 2.2 (RPO 0) — не указан механизм (sync replication? quorum?).
- Отсутствует требование по rate limiting → DoS-риск.
- Отсутствует требование по аудиту доступа к PAN → compliance-риск.

2. Как обрабатывать partial failure при retry (деньги списаны, ответ потерян)?
