# Вопросы и ответы

**Чем это отличается от «попросить модель написать код»?**
Модель пишет код, но вердикт даёт не она. Каждое требование получает статус из запущенных тестов, атак и правил; чего не доказали, то не `passed`.

**Нужен ли Vishap?**
Нет. Анализатор Vishap подключается как внешняя команда (`vishap analyze`) и нужен только если в spec стоит `check: analyzer`. Нет команды: проверка `skipped`, это видно в отчёте.

**Какая модель нужна?**
Любой OpenAI-совместимый endpoint: DeepSeek, Claude через совместимый шлюз, Ollama. Настройки только из окружения (`CUSTOM_LLM_*`), см. `.env.example`.

**Куда уходит моя spec?**
Провайдеру модели, если адрес не локальный. Не пишите в spec секреты и персональные данные.

**Безопасно ли запускать чужие spec?**
Нет, не без изоляции. Verify запускает код модели дочерним процессом с вашими правами. Для чужих spec используйте Docker (`deploy/README.md`).

**Что значит «stale»?**
Поле `updated` в spec старше 90 дней: вердикт по спецификации становится `stale`, а `--gate` блокирует запись.

**Почему гейт заблокировал, а файлы нужны?**
Причины перечислены в отчёте. Исправьте или запишите с `--force` (в трассе будет `forced: true`). Без `--gate` файлы пишутся всегда.

**Как отменить запись?**
`vishap-generator rollback <ID> --out <папка>`. ID печатается после прогона и лежит в `<out>/.vishap/runs/`.

**Почему тестов меньше, чем требований?**
Тест нужен на каждое требование, которое обслуживает тестовый файл. Нехватку находит проверка сборки, и модель получает её текст в раунде исправления.

**Где промпты?**
`src/generator/prompts/*.md`, описание в `prompts/README.md`.
