# Prompts

Модель вызывается в четырёх местах; у каждого свой файл. Файл — весь промпт: код добавляет в сообщение пользователя только данные (текст spec, требования, проблемы). Стиль и разделы как у промптов Vishap: Вход, Что делать, Самопроверка, Выход — JSON, Что запрещено, Тон.

| Файл | Этап | Кем используется |
|---|---|---|
| `00_rules.md` | все | добавляется в конец каждого системного промпта |
| `02_design_textcheck.md` | 2 Design | `pipeline/textcheck.py`: свободный текст против требований (только отчёт) |
| `03_build.md` | 3 Build | `pipeline/generate.py`: написать файлы; описывает, как Verify их проверит |
| `03_build_repair.md` | 3 Build | `pipeline/generate.py`: исправить после Verify (идёт в сообщении пользователя); есть блок «EARLIER ROUNDS» |
| `04_verify_cove.md` | 4 Verify | `pipeline/cove.py`: ответить по spec, что сервис делает на странных значениях (кода модель не видит); только при `--cove` |

Intake (1), Deliver (5) и вердикт Verify (4) без промпта намеренно: это детерминированный код, вердикт не зависит от модели. `04_verify_cove` только добавляет заметки и ни один статус требования не меняет.

Данные пользователя идут между случайными маркерами `VG_<ЯРЛЫК>_<hex>` (`pipeline/prompts.py`), поэтому текст внутри spec не может закрыть блок и сойти за инструкцию.

Промпт ссылается на то, что Verify реально делает (набор атак, `fullmatch`, порог 80%, правила `sql-from-input` и `log-raw-input`). Если меняешь Verify, меняй и `03_build.md`; `tests/test_prompts.py` ловит часть расхождений.
