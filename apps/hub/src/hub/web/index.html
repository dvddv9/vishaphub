how it works

One plan, seven stages, one verdict

  1. 1

    Analyse input

    Screen supplied code before generation.

  2. 2

    Generate

    The model proposes code from your spec. It proposes; it never decides.

  3. 3

    Analyse output

    Screen the generated code; findings from both scans are kept.

  4. 4

    Validate

    Six checks compare the generated code with the promise.

  5. 5

    Creator / corrected version

    Creator returns complete corrected files using the findings and original spec.

  6. 6

    Validate the correction

    Validator runs the six checks again against Creator's corrected files and the same spec.

  7. 7

    Final generator

    Generate the final complete version after validation. It is delivered clearly as not re-verified.

The strictest verdict wins. Whatever was not checked is listed, not hidden.

Model connection

Generation and Creator need a model. Your key stays in this browser and is sent with the run. Ollama needs no key.

Optional. Without a key only the rules run; with your key and a question the model reads the code as well, and the stricter verdict wins. The key is kept in this browser and sent with your run.

REQUIRES_REVIEW means a person should read the findings. Rules-only SAFE is currently eligible for Java after a complete scan with no findings; other languages remain in review.
